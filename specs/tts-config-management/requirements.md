# 需求文档 - TTS配置管理系统

## 介绍

当前项目中的TTS API配置（包括hostname、port、path、audioUrl、promptText）是写死在MCPConfig.ts文件中的。用户需要一个图形化界面来动态配置和管理这些TTS相关的设置，而不是通过修改代码的方式。本需求旨在在renderer包的工具栏中添加一个TTS配置按钮，提供完整的TTS配置管理功能。

## 需求

### 需求 1 - TTS配置按钮添加

**用户故事：** 作为应用用户，我希望在工具栏中看到一个TTS配置按钮，以便我可以访问TTS配置管理界面。

#### 验收标准

1. When 用户查看工具栏时，系统应当在工具栏中显示一个TTS配置按钮图标
2. When 用户点击TTS配置按钮时，系统应当打开TTS配置管理弹窗
3. When TTS配置按钮被hover时，系统应当显示"TTS配置"的提示文本
4. When TTS配置按钮被右键点击时，系统应当显示快速操作菜单（可选功能）

### 需求 2 - TTS配置管理界面

**用户故事：** 作为应用用户，我希望通过一个友好的界面来查看和编辑所有TTS相关的配置参数。

#### 验收标准

1. When 用户打开TTS配置界面时，系统应当显示当前所有TTS配置项（hostname、port、path、audioUrl、promptText）
2. When 用户修改任意配置项时，系统应当实时验证输入格式的有效性
3. When 用户修改hostname时，系统应当验证其为有效的域名或IP地址格式
4. When 用户修改port时，系统应当验证其为1-65535范围内的有效端口号
5. When 用户修改path时，系统应当验证其为有效的URL路径格式
6. When 用户修改audioUrl时，系统应当验证其为有效的HTTP/HTTPS URL格式
7. When 用户输入无效数据时，系统应当显示相应的错误提示信息

### 需求 3 - 配置保存与加载

**用户故事：** 作为应用用户，我希望我的TTS配置能够被持久化保存，并在下次启动应用时自动加载。

#### 验收标准

1. When 用户点击保存按钮时，系统应当将TTS配置保存到持久化存储中
2. When 配置保存成功时，系统应当显示"配置保存成功"的提示信息
3. When 配置保存失败时，系统应当显示具体的错误信息
4. When 应用启动时，系统应当自动加载之前保存的TTS配置
5. When 没有保存的配置时，系统应当使用系统原生语音功能，而不是TTS服务
6. When 用户点击重置按钮时，系统应当清空所有配置项并切换回系统原生语音功能

### 需求 4 - 配置测试功能

**用户故事：** 作为应用用户，我希望能够测试我配置的TTS服务是否正常工作，以确保配置的正确性。

#### 验收标准

1. When 用户点击测试连接按钮时，系统应当使用当前配置尝试连接TTS服务
2. When TTS连接测试成功时，系统应当显示"连接测试成功"的提示信息
3. When TTS连接测试失败时，系统应当显示具体的失败原因和错误信息
4. When 用户点击语音测试按钮时，系统应当使用当前配置播放一段测试语音
5. When 语音测试过程中时，系统应当显示"正在测试语音..."的加载状态
6. When 语音测试完成时，系统应当显示测试结果（成功或失败）

### 需求 5 - 界面设计和用户体验

**用户故事：** 作为应用用户，我希望TTS配置界面具有良好的视觉设计和用户体验。

#### 验收标准

1. When 用户打开TTS配置界面时，系统应当使用与应用整体风格一致的设计风格
2. When 配置界面显示时，系统应当使用毛玻璃效果的半透明背景
3. When 用户在界面中操作时，系统应当提供平滑的动画过渡效果
4. When 用户点击界面外部区域时，系统应当关闭配置弹窗
5. When 用户按ESC键时，系统应当关闭配置弹窗
6. When 界面响应用户操作时，系统应当在100ms内做出响应
7. When 表单验证发生时，系统应当使用红色边框和错误信息突出显示错误字段

## 技术要求

- 遵循现有的工具栏按钮实现模式
- 使用React函数组件和TypeScript
- 配置数据通过IPC通信与Electron主进程交互
- 使用现有的ConfigService进行配置持久化
- 保持与现有VoiceSettings组件相似的界面风格
- 支持配置的实时验证和错误提示
