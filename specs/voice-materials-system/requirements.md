# 需求文档

## 介绍

为了增强用户体验，需要在Cursor IDE对话完成时播放多样化的语音提示。当前系统只支持简单的TTS语音，用户希望有更丰富、更具个性的语音反馈，让虚拟角色能够以不同的语音风格来提示对话完成。

## 需求

### 需求 1 - 多样化语音素材系统

**用户故事：** 作为一个使用虚拟角色助手的开发者，我希望在与Cursor IDE对话完成时，能听到多种不同风格的语音提示，而不是单调的TTS语音，让交互体验更加生动有趣。

#### 验收标准

1. When 调用MCP的conversation_complete工具时，系统应当随机或按配置选择一个预设的语音文件进行播放。
2. While 系统中存在多个语音素材文件时，系统应当支持至少5种不同风格的完成语音提示。
3. When 播放语音时，系统应当根据urgency参数选择对应情绪的语音素材（normal、high、low）。
4. When 语音文件不存在或播放失败时，系统应当fallback到TTS语音作为备选方案。
5. When 用户配置了语音偏好时，系统应当优先使用用户选择的语音风格。

### 需求 2 - 语音素材管理

**用户故事：** 作为系统管理员，我希望能够方便地管理和扩展语音素材库，包括添加、删除、分类语音文件。

#### 验收标准

1. When 系统启动时，应当扫描并加载所有可用的语音素材文件。
2. While 添加新的语音文件时，系统应当自动识别并分类语音文件（按情绪或风格）。
3. When 语音文件损坏或缺失时，系统应当记录错误日志并自动排除该文件。
4. When 开发模式下，系统应当提供语音素材的预览和测试功能。

### 需求 3 - 配置化语音选择

**用户故事：** 作为用户，我希望能够自定义语音提示的行为，包括选择喜欢的语音风格、调整播放频率等。

#### 验收标准

1. When 用户打开设置面板时，应当能够看到语音配置选项。
2. While 选择语音风格时，用户应当能够预览不同语音的效果。
3. When 用户禁用语音提示时，系统应当只播放系统提示音。
4. When 用户设置了自定义语音文件夹时，系统应当从该文件夹加载语音素材。

### 需求 4 - TTS与固定语音切换

**用户故事：** 作为开发者，我希望能够在预设的固定语音和动态TTS语音之间灵活切换，根据不同场景选择最合适的语音反馈方式。

#### 验收标准

1. When 用户在设置中开启"动态TTS模式"时，系统应当优先使用TTS引擎生成语音而非固定语音文件。
2. While 在TTS模式下，系统应当能够将对话内容的关键信息转换为语音播放。
3. When TTS服务不可用或失败时，系统应当自动fallback到固定语音素材。
4. When 用户选择"混合模式"时，系统应当根据消息类型智能选择TTS或固定语音。

### 需求 5 - 项目总结语音播放

**用户故事：** 作为开发者，我希望系统能够智能提取当前工作项目的简单总结，并在对话完成时用语音播放，让我了解当前的工作状态和进展。

#### 验收标准

1. When 对话完成时，系统应当能够分析当前Cursor IDE的项目内容和最近的代码修改。
2. While 生成项目总结时，系统应当包含文件修改数量、主要改动类型、当前任务状态等关键信息。
3. When 项目总结生成完成时，系统应当使用TTS将总结内容转换为语音播放。
4. When 项目总结过长时，系统应当自动精简内容，确保语音播放时长在30秒以内。
5. When 无法获取项目信息时，系统应当播放默认的完成提示语音。
